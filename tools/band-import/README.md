# Band 게시글 가져오기 (Mac 로컬, MVP)

운영자가 **직접 운영하는 밴드**의 게시글 하나를 로컬로 가져오는 도구입니다.
제목/본문/이미지/일정 정보를 `out/{postId}/`에 저장하고, 확인한 뒤 버튼 한 번으로 오고피씽 앱에 등록합니다(조황은 조황 사진 게시판, 일정은 출조 일정).

## 주의 (Band 이용약관)

- 로그인된 브라우저를 자동화하는 방식이라 Band 약관에 어긋날 수 있습니다. 본인 밴드만, 필요한 게시글만, 한 번에 하나씩 가져오세요. 반복 수집이나 대량 수집에 쓰지 마세요.
- Band 웹 내부 API와 화면 구조는 공개 규격이 아니어서 예고 없이 바뀔 수 있습니다.
- `user-data/`에는 Band 로그인 쿠키가, `out/`에는 회원이 올린 글과 사진이, `ohgo-local/`에는 오고피씽 관리자 로그인 토큰, 등록 장부, 새 글 확인 상태(`band-check-state.json`)가 들어 있습니다. 모두 gitignore 되어 있으니 커밋하거나 공유하지 마세요. Mac 디스크 암호화(FileVault)를 켜 두세요.

## 설치

저장소 루트에서 한 번만 실행합니다. Node 22.6 이상이 필요합니다(`.mts`를 `--experimental-strip-types`로 실행).

```bash
npm install
npx playwright install chromium
```

설치된 Chrome을 쓰고 싶으면 명령 앞에 `BAND_BROWSER_CHANNEL=chrome`을 붙이세요.

## Mac 앱으로 쓰기 (권장)

### 실행

```bash
npm run band:gui
```

작은 창이 뜹니다.

1. 처음 한 번 **로그인**을 누릅니다. Band 창이 열리면 로그인하세요. 로그인이 확인되면 창이 자동으로 닫히고 `로그인 세션 저장됨`으로 바뀝니다.
2. Band 게시글 주소를 입력칸에 붙여넣고(Cmd+V 또는 **붙여넣기** 버튼) **가져오기**를 누릅니다(Enter도 됨).
3. 끝나면 제목, 이미지 수, 썸네일이 보입니다. **결과 폴더 열기**를 누르면 Finder에서 `out/{postId}/`가 열립니다.
4. 아래 **오고피씽에 등록** 칸에서 내용을 확인하고 **오고피씽에 등록**을 누릅니다. 자세한 내용은 [오고피씽에 등록](#오고피씽에-등록)을 보세요.

- 가져오기는 기본으로 Band 창을 띄워서 진행합니다. 창은 끝나면 자동으로 닫히니 건드리지 마세요. 진행 중에 창을 닫으면 작업이 멈춥니다.
- **브라우저 창 없이 가져오기**를 켜면 창 없이 진행하고, 로그인이 안 된 것으로 보이면 자동으로 창을 띄워 한 번 더 시도합니다.
- 다 쓰면 **종료**를 누르거나 Cmd+Q로 끕니다. 진행 중인 작업이 있으면 끝난 뒤 종료합니다.
- 앱 창 대신 기본 브라우저 탭으로 열고 싶으면 `BAND_GUI_OPEN=browser npm run band:gui`를 쓰세요.

### Dock/Launchpad에서 실행하는 .app 만들기 (선택)

```bash
npm run band:app
```

`tools/band-import/dist/Band 가져오기.app`이 만들어집니다. Finder에서 응용 프로그램 폴더로 옮긴 뒤 더블클릭하면 됩니다.

- 이 앱은 저장소 위치를 기억해서 `npm run band:gui`를 대신 실행하는 껍데기입니다. 저장소를 다른 곳으로 옮기면 `npm run band:app`을 다시 실행하세요.
- 서명되지 않은 앱이라 처음에는 "확인되지 않은 개발자" 경고가 뜹니다. Finder에서 앱을 Control+클릭하고 **열기**를 고르세요.
- 실행 로그는 `~/Library/Logs/band-import-gui.log`에 쌓입니다.

#### 앱 아이콘

- 아이콘은 오고피씽 앱 로고(`mobile/assets/icon.png`)를 중심에 두고, 오른쪽 아래에 Band 느낌의 초록 배지(흰 b)와 두 화살표 동기화 표시를 더한 `tools/band-import/mac/AppIcon.png`입니다. Band 배지는 Band 로고 파일이 아니라 단순 도형으로 직접 그린 것입니다. 32px 이하에서는 동기화 표시가 뭉개져서 빼고 배지를 키웠습니다.
- `npm run band:app`은 저장소에 커밋된 `mac/AppIcon.icns`를 그대로 앱에 복사합니다. 이 파일에는 16, 32px용 단순화 그림이 따로 들어 있어서, `sips`, `iconutil`로 1024 PNG를 줄여 다시 만들지 않습니다.
- 아이콘을 다시 만드는 방법은 `npm run band:icon` 하나뿐입니다. 로고를 바꿨으면 이 명령으로 `AppIcon.png`, `AppIcon.icns`, GUI 창 아이콘(`gui/favicon.png`)을 다시 만들어 커밋한 뒤 `npm run band:app`을 실행하세요.
- Finder나 Dock이 예전 아이콘(빈 아이콘)을 계속 보여 줄 수 있습니다. 아이콘 캐시 때문이며, 아래 순서대로 해 보세요.
  1. `npm run band:app`으로 다시 만든 뒤 응용 프로그램 폴더의 예전 앱을 지우고 새로 옮깁니다.
  2. 그래도 그대로면 `touch "/Applications/Band 가져오기.app"`을 실행하고 Finder 창을 닫았다 엽니다.
  3. 마지막으로 `killall Finder; killall Dock`을 실행합니다(Finder와 Dock만 다시 뜹니다).

## 오고피씽에 등록

가져오기가 끝나면 GUI 아래에 **오고피씽에 등록** 칸이 나옵니다. 아무것도 바로 올라가지 않고, 운영자가 **오고피씽에 등록** 버튼을 눌러야 저장됩니다.

### 처음 한 번: 관리자 로그인

- 앱에 로그인할 때 쓰는 **이름**과 **생년월일**(6자리 또는 8자리)을 넣고 **관리자 로그인**을 누릅니다. 앱과 같은 로그인 API(`/api/auth/legacy-login`)를 쓰며, 등록되지 않은 이름이면 가입하지 않고 실패합니다.
- 관리자(`profiles.role = 'admin'`)가 아니면 로그인을 거절하고 아무것도 저장하지 않습니다. 등록은 이 관리자 토큰으로 Supabase에 직접 쓰므로 앱의 RLS(`is_admin()`)를 그대로 통과해야 합니다. service_role 키는 쓰지 않습니다.
- 이메일과 비밀번호가 있는 Supabase 계정이면 **이메일 계정으로 로그인**을 눌러 쓸 수 있습니다.
- 이름, 생년월일, 비밀번호는 저장하지 않습니다. Supabase 로그인 토큰만 `tools/band-import/ohgo-local/session.json`(본인만 읽기, 0600)에 저장하고, 만료되면 자동으로 갱신합니다. 갱신 토큰은 한 번 쓰면 서버가 지우고 새 것을 주므로, 갱신은 한 번에 하나만 하고 새 토큰은 잠금을 풀기 전에 원자적으로 저장합니다(앱을 두 개 띄우거나 저장 전에 꺼지면 서버가 토큰을 폐기해 "Refresh Token Not Found"가 납니다). 갱신이 안 되면 등록 칸과 계정 칸에 **다시 로그인**이 나오고, 로그인하면 멈추기 전의 등록(순서, 뺀 사진, 편집, 서식)을 그대로 다시 시도합니다. 로그인이 확인되기 전에는 사진을 올리지 않습니다.
- **로그아웃**을 누르면 저장한 토큰을 지웁니다.

### 조황 사진 게시판 / 출조 일정 고르기

글 내용으로 자동 분류하고, 위쪽 두 버튼으로 바꿀 수 있습니다. 분류 근거(제목, 일정 첨부, 단어, 게시일 이후 날짜, 사진 수)가 함께 보입니다. 제목에 "조황"이 있거나 사진이 많으면 이벤트 안내나 예약 문구가 섞여 있어도 조황으로 고릅니다. 출조 일정에는 사진이 올라가지 않으니, 사진이 있는 글을 출조 일정으로 두면 화면에 알림이 뜹니다.

**조황 사진 게시판** (`community_photos`, `board_type = 'photo'`)

- 제목은 Band 글 첫 줄을 정리해서, 내용은 나머지 본문, 사진 날짜는 게시일(한국 시간)로 채웁니다. 모두 고칠 수 있습니다. 화면(DOM)으로 가져온 글은 게시일을 몰라 사진 날짜가 비어 있으니 직접 넣으세요.
- 게시판 목록과 글 화면은 `photo_date`가 아니라 `created_at`으로 날짜를 보여주고 정렬합니다. 그래서 사진 날짜를 `photo_date`와 `created_at`에 같이 넣습니다. 그 날짜가 Band 글의 한국 날짜와 같으면 Band에 올린 시각을 쓰고, 아니면 그날 12:00(한국 시간)을 씁니다. 사진 날짜 아래에 게시판에 보일 시각을 보여 줍니다. 사진 날짜를 비우면 등록한 시각(`created_at` 기본값)으로 올라갑니다.
- 제목 정리: 맨 앞 "오늘/내일/금일" 다음에 날짜가 오면 그 말을 빼고, 날짜(`6일(화)`) 뒤, `이벤트N주차` 앞뒤, 어종+조황(`감성돔조황`) 앞, 끝의 `입니다` 앞을 띄웁니다. 예: `오늘6일(화)이벤트4주차감성돔조황입니다.` → `6일(화) 이벤트4주차 감성돔조황 입니다.`
- 사진은 `extracted.json` 목록과 `out/{postId}/` 폴더를 맞춰 봅니다. 목록에 없어도 폴더에 받아 둔 `01.jpg` 같은 사진은 넣고, 목록에만 있고 폴더에 없는 사진이나 올릴 수 없는 형식(heic 등)은 빼면서 알려 줍니다.
- API로 가져온 글의 사진 순서는 Band 본문의 사진 자리(`<band:attachment>`) 순서를 따릅니다. Band가 사진 목록을 배열이 아니라 `{사진id: 사진}` 묶음으로 줄 때도 읽습니다.
- 썸네일 왼쪽 위 번호가 올라가는 순서입니다(앱에서 보이는 순서와 같음). 사진을 끌어다 놓으면 순서가 바뀝니다.
- 사진 아래 **✕ 빼기**를 누르면 그 사진을 올리지 않습니다. 뺀 사진은 흐리게 "뺌"으로 보이고 버튼이 **다시 넣기**로 바뀌며, 남은 사진의 번호가 당겨집니다. 순서를 바꿔도 뺀 상태는 그 사진에 남습니다. 고른 사진만 Storage `photos` 버킷의 `community/photos/photo_{시각}_{임의값}.{확장자}`에 올립니다(앱의 사진 올리기와 같은 경로).
- 사진을 누르면 편집 창이 열려 사진 한 장을 자르기(자유, 4:3, 1:1, 3:4), 왼쪽/오른쪽으로 돌리기, 좌우 뒤집기 할 수 있습니다. 저장하면 원본은 그대로 두고 `out/{postId}/edited_01.jpg` 같은 편집본을 만들어 그것을 올립니다(편집 내용은 `edits.json`). 썸네일에 "편집됨"이 붙고, 편집 창의 **원본으로 되돌리기**로 편집본을 지웁니다. JPEG는 품질 90%로 저장하고, PNG는 투명 배경을 살려 PNG로 둡니다.
- Band 본문의 **글자색, 배경색, 굵게, 기울임, 밑줄, 취소선, 글자 크기**는 기본으로 살립니다. 미리보기가 내용 칸 아래에 보이고, 체크를 끄면 서식 없이 올립니다. 내용 칸을 고치면 체크가 자동으로 꺼집니다(서식을 살리면 앱은 미리보기 쪽을 보여 주고 내용 칸은 보이지 않기 때문).
  - 서식을 살리면 `content`에 HTML을, `description`에는 지금처럼 평문을 넣습니다. 앱 상세 화면은 `content`를 그대로 그리므로, 만드는 HTML은 CKEditor 5가 같은 서식을 저장할 때의 모양만 둡니다. 문단은 `<p>`, 굵게는 `<strong>`, 기울임은 `<i>`, 취소선은 `<s>`, 밑줄은 `<u>`, 색과 크기는 `<span style="background-color:#…;color:#…;font-size:18px;">`입니다. 링크, 이미지, 스크립트 등 다른 태그와 속성은 버리고 글자는 이스케이프합니다. 등록할 때 화면에서 HTML을 받지 않고 `extracted.json`에서 다시 만듭니다.
  - 글자색(`color01`~`color11`)은 Band 웹 스크립트(boot.bundle.js, 2026-10-07)의 색표입니다. 배경색 태그(`band:bgcolor`)는 그 스크립트에 없고, 화면 HTML의 `background-color`가 같은 11색일 때만 남깁니다. 글자 크기는 `l`이 18px, `xl`이 22px입니다. 기울임은 `<i>`, 밑줄은 `<u>`, 취소선은 `<del>`입니다. 해시태그와 멘션은 글자로, 사진/동영상 자리는 없앱니다.
  - 지금 앱 에디터(CKEditor 5 classic 빌드)는 문단, 굵게, 기울임만 유지합니다. 글자색, 배경색, 밑줄, 취소선, 글자 크기는 글 화면에는 보이지만, 앱에서 글을 고치면 빠집니다. 수정 화면에서도 남기려면 앱 에디터 빌드에 그 플러그인을 넣고 배포해야 합니다. 이 도구는 앱 코드를 바꾸지 않습니다.
  - 이번 기능 전에 가져온 글은 원래 본문이 저장되어 있지 않아 서식 없이 올라갑니다. 서식을 살리려면 다시 가져오세요.
- 5MB가 넘는 사진은 JPEG로 줄여서 올립니다(긴 변 2560px부터 단계적으로).
- 사진은 한 장이라도 못 올리면 거기서 멈추고 글을 만들지 않습니다(사진 없는 글을 만들지 않음). 방금 올린 사진은 지웁니다. 서버 권한 때문에 못 지운 사진이 있으면 몇 장 남았는지 알려 줍니다(앱에는 보이지 않습니다).
- 글을 저장한 뒤 다시 읽어 `image_urls`가 올린 사진과 같은지, 사진마다 공개 주소가 열리는지 확인합니다. 어긋나면 글과 사진을 지우고 실패로 알립니다. 글을 못 지웠으면 직접 지울 앱 주소를 보여 줍니다.
- 실패하면 등록 버튼 바로 아래 빨간 칸에 몇 번째 사진(편집본이면 그 파일 이름)이 왜 실패했는지 나옵니다. 서버가 영어로 답한 이유(크기 초과, 권한 거절, 로그인 만료 등)는 우리말 설명을 붙입니다.
- 등록할 때마다 `out/{postId}/push-log.json`에 기록을 남깁니다(최근 5번). 사진별 파일 이름, 크기, 형식, 줄였는지, 서버 요청마다 주소, 응답 코드, 응답 앞부분이 들어 있습니다. 로그인 토큰, 키, 로그인 응답은 적지 않습니다. 문제가 생기면 **기록 폴더 열기**를 눌러 이 파일을 보내 주세요.

**출조 일정** (`trip_guides`)

- 화면은 표입니다. 한 줄이 앱의 출조 일정 한 건이고, 줄마다 날짜, 어종, 출항, 입항, 1인 요금, 비고를 고칠 수 있습니다. 목적지, 정원, 예약 문의는 모든 줄에 같이 들어갑니다.
- 주간 일정 글: `5일 (월) 감성돔 06시 출항 예약마감` 같은 날짜별 줄을 하나씩 출조로 만듭니다.
  - 월은 머리말 `10월 5일 ~ 10월 11일`에서, 연도는 게시일(없으면 가져온 날)에서 정합니다. 12월에서 1월로 넘어가는 주도 맞게 정합니다. 요일이 날짜와 다르면 알려 줍니다.
  - 시간은 `06시`, `6시30분`, `06:30`, `오전 6시`를 읽습니다. 한 줄에 `감성돔 06시 출항, 오후 문어 1시 출항`처럼 어종이 둘이면 두 건으로 나눕니다(`오후`가 붙은 쪽은 13시).
  - `예약마감`, `자리여유`, `휴항` 같은 상태는 앱에 상태 칸이 없어 비고에 넣습니다. 앱의 "정원 마감"은 예약 수가 정원에 닿을 때만 보여서 여기에 맞출 수 없습니다. 휴항, 취소 줄은 체크를 꺼 둡니다.
  - 요금은 아래 안내 줄에서 같은 어종의 선비(`감성돔선비10만원` → 100000)를 씁니다. 입항 시간은 그 줄이나 같은 어종 안내에 적혀 있을 때만 넣습니다. 같은 어종에 값이 둘 이상이면 비우고 알려 줍니다.
  - 선비, 최소출항인원, 신분증, 문의전화, 계좌, 해시태그 같은 안내 줄은 출조가 되지 않고 비고에도 들어가지 않습니다. 계좌 번호가 있는 줄은 어떤 경우에도 비고에 넣지 않습니다.
- 날짜별 줄이 없는 글: Band 일정 첨부 날짜, 또는 본문의 `10월 12일`, `10/12`, `2026.10.12`, `내일`로 줄을 만들고, `출항 05:30`, `새벽 5시 반 출항`, `출항 05:00 ~ 14:00` 같은 시간을 채웁니다. `집결`, `승선` 시각은 출항 시각이 없을 때만 씁니다.
- 목적지: `목적지:`, `포인트:` 같은 표시나 앱에 이미 있는 목적지 이름이 글에 있으면 그것, 없으면 앱에서 가장 많이 쓴 목적지(지금은 낫개)를 넣고 알려 줍니다. 예약 문의는 글의 첫 휴대폰 번호입니다.
- 줄마다 앱에 같은 날짜의 출조가 이미 있으면 그 줄 아래에 보여 줍니다. 체크를 끈 줄은 저장하지 않고, "+ 줄 추가"로 줄을 더할 수 있습니다.
- 빨간 칸(날짜, 출항 시간, 목적지, 형식이 틀린 값)을 고쳐야 등록 버튼이 켜집니다. 체크한 줄을 한 번에 저장하고, 하나라도 실패하면 이번에 저장한 줄을 모두 지웁니다.

- 장부 파일이 깨졌으면 등록을 멈춥니다(조용히 비우지 않음).

기본은 운영 `https://ohgo.codejaka.com`입니다. Supabase 주소와 공개 anon 키는 이 사이트의 웹 번들에서 실행할 때마다 읽어 오므로 따로 넣을 것이 없습니다. 다른 곳에 연결하려면 환경 변수를 씁니다.

```bash
OHGO_BASE_URL=http://localhost:3000 OHGO_SUPABASE_URL=https://xxxx.supabase.co OHGO_SUPABASE_ANON_KEY=eyJ... npm run band:gui
```

`.app`으로 실행할 때 환경 변수가 필요하면 `~/.zshrc`에 `export`로 넣으세요(앱이 로그인 셸로 실행합니다). 저장한 로그인은 Supabase 프로젝트별이라, 다른 프로젝트로 바꾸면 다시 로그인하라고 나옵니다.

## 터미널로 쓰기

### 1. 로그인 (처음 한 번)

```bash
npm run band:login
```

브라우저 창이 열리면 Band에 로그인합니다. 로그인이 확인되면 창이 자동으로 닫히고 세션이 `tools/band-import/user-data/`에 저장됩니다. 이미 로그인되어 있으면 바로 끝납니다. 세션이 만료되면 다시 실행하세요.

Band 로그인 쿠키 일부는 브라우저를 닫으면 사라지는 세션 쿠키입니다. 그래서 login이 끝날 때 Band 쿠키와 브라우저 정보(User-Agent)를 `user-data/band-session.json`에 따로 저장하고, fetch가 시작할 때 되살립니다. 이 기능이 생기기 전에 로그인했다면 로그인을 한 번 다시 실행하세요.

### 2. 게시글 가져오기

```bash
npm run band:fetch -- https://band.us/band/88348442/post/2925
```

결과:

```
tools/band-import/out/2925/
  extracted.json   # 추출 결과
  01.jpg 02.jpg …  # 원본 이미지
  api-post.json    # Band API 원본 응답(디버깅용, API로 추출했을 때만)
  network-log.json # 받은 Band 응답 주소 목록(디버깅용, 쿼리스트링 제외)
```

기본은 창 없이 진행하고, 로그인이 안 된 것으로 보이면 창을 띄워 한 번 더 시도합니다.

옵션:

| 옵션 | 설명 |
| --- | --- |
| `--headed` | 처음부터 브라우저 창을 띄워서 진행 |
| `--no-headed-fallback` | 창 없이 실패해도 창 모드로 다시 시도하지 않음 |
| `--timeout 30` | 게시글 로딩 대기 시간(초) |
| `--out DIR` | 저장 위치 변경 (기본 `tools/band-import/out`) |
| `--dry-run` | 브라우저 없이 URL 해석 결과와 저장 경로만 출력 |

저장된 파일 검사:

```bash
npm run band:validate -- tools/band-import/out/2925/extracted.json
```

### 3. 새 글만 확인 (등록하지 않음)

한 시간에 한 번, 사람 없이 밴드에 새 글이 있는지만 볼 때 씁니다. 글을 가져오거나 오고피씽에 등록하지 않고, Band에도 글을 쓰지 않습니다. 확인은 창 없는 브라우저로만 하고 로그인을 묻지 않습니다. 로그인이 만료되면 알려 주기만 합니다. 등록은 지금까지처럼 Mac 앱에서 합니다.

저장소 루트에서, 로그인 셸로, 표준 출력에는 JSON 한 줄만 나오게 실행합니다.

```bash
cd /Users/ynjeong/Documents/CodejakaProjects/ohgo-coupon-web && zsh -lc 'npm run -s band:check'
```

`npm run -s`의 `-s`를 빼면 npm이 명령 이름을 표준 출력에 찍어서 JSON이 깨집니다. 같은 명령은 `node --experimental-strip-types --no-warnings=ExperimentalWarning tools/band-import/src/check-cli.mts check`로도 실행됩니다. 기존 `cli.mts`의 login/fetch와는 별도 파일입니다. `band:login`이 저장한 `user-data/` 세션을 그대로 씁니다. `BAND_USER_DATA_DIR`, `BAND_OHGO_DIR`를 바꿨다면 login과 같은 값이어야 합니다.

성공하면 종료 코드 0, 표준 출력은 아래 한 줄입니다. 진행 문구는 표준 오류로만 나갑니다.

```json
{"status":"ok","checkedAt":"2026-10-08T19:00:00.000+09:00","baseline":false,"newPosts":[{"postNo":3101,"url":"https://band.us/band/88348442/post/3101","createdAt":"2026-10-08T18:40:00.000+09:00","author":"오고피싱 선장","snippet":"오늘 감성돔 조황입니다","photoCount":6,"kind":"조황"}]}
```

- 대상은 밴드 `88348442` (`https://band.us/band/88348442`) 입니다. 최근 글 20개 안팎을 읽습니다. Band 웹 JSON에서 `post_no`가 있는 글을 찾고, 그게 없으면 화면의 게시글 링크를 씁니다.
- `createdAt`과 `checkedAt`은 한국 시간(UTC+9) ISO 8601입니다. `kind`는 기존 분류로 `조황`, `일정`, `기타` 중 하나입니다. 목록만으로 분류할 내용이 없으면 `kind`를 뺍니다.
- 상태 파일은 `tools/band-import/ohgo-local/band-check-state.json`(본인만 읽기, 0600)입니다. 파일이 없으면 첫 실행으로 보고, 읽은 글을 모두 본 것으로 기록한 뒤 새 글 0건과 `"baseline":true`를 출력합니다.
- 다음부터는 아직 안 본 글만 `newPosts`에 넣고, 출력한 뒤에 본 목록에 더합니다. 같은 글은 한 번만 새 글입니다. 이미 본 글 중 가장 최근 시각보다 2일 더 오래된 글은 알리지 않습니다.
- 로그인이 없거나, 로그인 페이지로 갔거나, 멤버만 볼 수 있으면 종료 코드 2입니다. 본 목록은 바꾸지 않습니다.

```json
{"status":"login_required","checkedAt":"2026-10-08T19:00:00.000+09:00","message":"Band 로그인이 만료되었습니다 (상태: NONE). npm run band:login 을 다시 실행하세요."}
```

- 네트워크 오류, 시간 초과(약 60초), 화면을 읽지 못함, 이미 실행 중이면 종료 코드 1입니다. 본 목록은 바꾸지 않습니다.

```json
{"status":"error","checkedAt":"2026-10-08T19:00:00.000+09:00","message":"already running"}
```

```json
{"status":"error","checkedAt":"2026-10-08T19:00:00.000+09:00","message":"밴드 목록을 60초 안에 열지 못했습니다."}
```

두 번이 겹치지 않게 `ohgo-local/band-check.lock`으로 잠급니다. 프로세스가 이미 죽었거나 잠근 지 3분이 지난 잠금은 치웁니다.

## extracted.json

```jsonc
{
  "schemaVersion": 1,
  "source": { "url": "https://band.us/band/88348442/post/2925", "bandId": "88348442", "postId": "2925", "fetchedAt": "2026-10-06T22:00:00.000Z" },
  "extractedVia": "api",          // "api" 또는 "dom"(화면 폴백)
  "author": "작성자 이름",
  "createdAt": "2026-10-06T03:34:25.874Z",
  "title": "본문 첫 줄 (Band 글에는 제목이 없음)",
  "body": "본문 평문",
  "images": [{ "index": 0, "sourceUrl": "https://…pstatic.net/…", "file": "01.jpg", "width": 1080, "height": 1440 }],
  "schedules": [{ "name": "갈치 출조", "description": null, "startAt": "…", "endAt": "…", "isAllDay": false }],
  "scheduleLikeLines": ["출항 05:30 다대포항"],
  "warnings": [],
  "rawContent": { "format": "band", "html": "<band:color value=\"color02\">감성돔</band:color> …" }
}
```

- `file`이 `null`이면 해당 이미지 다운로드에 실패한 것입니다.
- `rawContent`는 글자색과 굵게 등이 남아 있는 원래 본문입니다. API로 가져오면 Band 마크업(`format: "band"`), 화면으로 가져오면 본문 요소의 HTML(`format: "dom"`)입니다. 분류와 일정 읽기는 지금처럼 `body` 평문을 씁니다.
- `schedules`는 Band 일정 첨부가 있을 때만 채워집니다. `scheduleLikeLines`는 본문에서 날짜/시간 패턴이 보이는 줄을 단순히 골라낸 것입니다.

## 동작 방식

1. 저장된 프로필로 Chromium을 열고 게시글 URL로 이동합니다.
2. Band 웹이 받는 `*.band.us` JSON 응답 중 `post_no`가 일치하는 게시글 객체를 찾습니다. 게시글 상세는 배치 API(`bapi.band.us/v2.0.0/batch`)로 오는데, 경로에 의존하지 않고 응답 내용을 검사합니다.
3. API 응답을 못 찾으면 화면(DOM)에서 본문과 사진을 읽습니다. 이 경우 사진이 일부만 잡힐 수 있어 `warnings`에 표시됩니다.
4. 로그인 여부는 Band 웹이 부팅할 때 받는 `auth.band.us` 응답의 로그인 상태 값(`authenticateState`)으로 판단합니다. 창 없이 실행할 때는 User-Agent의 `HeadlessChrome` 표시를 login 때 값으로 바꿉니다. 이 표시가 있으면 같은 쿠키로도 Band가 로그인으로 보지 않을 수 있습니다.
5. 이미지는 0.4초 간격으로 하나씩 받습니다.

## 로그인이 자꾸 풀릴 때

- 오류 메시지의 `(로그인 상태: NONE, Band 쿠키 n개)`는 Band 서버가 로그인 안 됨으로 응답했다는 뜻입니다. `npm run band:login`을 다시 실행하고 `세션 저장: Band 쿠키 …개`가 출력되는지 확인하세요.
- login 창을 닫기 전에 fetch를 실행하면 같은 프로필을 동시에 쓸 수 없어 실패합니다. 창이 닫힌 뒤 실행하세요.
- `BAND_USER_DATA_DIR`를 지정했다면 login과 fetch에 같은 값을 써야 합니다. 두 명령 모두 처음에 `브라우저 프로필:` 경로(절대 경로)를 출력하니 같은지 비교해 보세요.
- 창 없이 가져오기가 계속 실패하면 창 모드(앱 기본값, 터미널은 `--headed`)로 쓰세요. 창 모드에서 되면 문제는 headless 판정 쪽입니다.

## 테스트

Band 계정이나 오고피씽 계정 없이 돌아갑니다. URL 해석, 정규화, 스키마, 세션 저장, GUI 서버 단위 테스트와, 가짜 Band 페이지/API를 띄워 fetch 흐름 전체를 확인하는 오프라인 테스트가 있습니다. 오고피씽 등록은 조황/일정 분류, 날짜/시간/목적지 해석, 장부, 그리고 가짜 오고피씽 웹과 Supabase로 로그인, 사진 올리기, 저장, 실패 시 정리까지 확인합니다. 편집본 9장 중 두 번째가 서버에서 거절되고 정리도 조용히 안 되는 경우, 저장한 글의 `image_urls`가 비어 읽히는 경우, 공개 주소가 안 열리는 경우를 가짜 서버로 만들어 글이 남지 않고 이유와 기록 파일이 나오는지 봅니다. 사진 순서 바꾸기, 편집 창, 서식 미리보기는 실제 화면을 Chromium에 띄워 눌러 보고, 사진 편집은 Chromium으로 만든 그림의 크기와 픽셀 위치로, 서식 HTML은 스크립트, onerror, javascript: 주소 같은 공격 문자열을 브라우저에 넣어 허용한 태그만 생기는지 확인합니다.

```bash
npm run test:band-import
```
